PRODUCT MASTER DATA UI REDESIGN PROMPT

You are a senior product designer and frontend design-system architect.

Design a complete, production-ready UI redesign for an internal Product Master Data web application.

The UI will later be implemented inside an existing React + TypeScript + Vite codebase. Do not redesign the backend, database, API contracts, authentication rules, or business logic. Focus only on the frontend visual system, layout, interaction design, responsive behavior, and component structure.

PRODUCT CONTEXT

This application manages product master data imported from Excel.

The main user workflow is:

1. The user signs in.
2. The user sees a visual library of customers/companies.
3. Each customer card should prioritize a large PIC image.
4. The user clicks a customer.
5. The user sees all product items belonging to that customer.
6. Each item card should prioritize a large PIC image so the user can visually identify and select the item.
7. The user clicks an item to inspect all 27 source fields.
8. The user can create, edit, soft-delete, audit, search, filter, and import Excel data.
9. The user can review import history and validation errors.

TYPOGRAPHY

Use a modern sans-serif with strong readability.

Preferred font stack:

- Primary: Geist Sans, Inter, ui-sans-serif, system-ui, sans-serif

Typography rules:

- Page title: 32–40px, semibold or bold, tight letter spacing
- Section title: 18–22px, semibold

- Keep line lengths readable
- Use tabular numerals for counts, prices, quantities, and pagination

CUSTOMER LIBRARY PAGE

This is the most important screen.

Create an image-first customer library.

Header area:

- Page title: “Customer Library” or localized equivalent
- Short explanation
- Total customer count
- Search input
- Optional sorting control
- Primary action for creating a new record if authorized

Customer card:

- Large image area at the top
- Use the representative PIC image when available
- Use a refined placeholder when no image exists
- Customer/company name
- Number of items
- Optional small metadata such as region or latest update
- Entire card is keyboard accessible
- Clear hover, pressed, selected, and focus states

Customer card image behavior:

- Aspect ratio approximately 4:3 or 16:10
- Object-fit: cover
- Avoid distorted images
- Use a subtle neutral image background
- Use a small “No PIC” placeholder, not a broken-image icon

Grid:

- Tablet: 2 columns
- Mobile: 1 column
- Cards should have consistent heights
- Maintain generous gutters

PIC IMAGE BEHAVIOR

The PIC field may contain a Google Drive link.

The UI must support:

- Google Drive file links
- Google Drive open links
- Google Drive thumbnail links
- Regular HTTPS image URLs
- Invalid or missing URLs

For Google Drive links:

- Extract the file ID
- Convert it into a browser image URL such as:
  https://drive.google.com/thumbnail?id=FILE_ID&sz=w1600
- Show a graceful fallback if the file is private, deleted, unavailable, or not an image
- Do not expose a broken image layout
- Do not fetch arbitrary URLs through the backend
- Only render safe HTTPS image sources

Make it clear in the design that the Google Drive file must be shared as:
“Anyone with the link — Viewer”
Do not place this instruction inside the main product UI unless it belongs in an import/help state.

SEARCH AND FILTERS

Search should feel fast and focused.

Customer-level search:

- Search company/customer names
- Show result count
- Show a clear empty state
- Preserve search text when navigating back

Item-level search:

- Search across all supported product fields
- Allow expanding the filter panel
- Include all 27 source fields in the filter UI
- Use a clean two- or three-column filter layout on desktop
- Collapse to one column on mobile
- Clearly distinguish global search from field filters
- Provide “Apply filters” and “Clear filters”
- Reset pagination after applying filters

Pagination:

- Show current page and total pages
- Disable unavailable actions
- Keep pagination stable on mobile
- Do not use infinite scroll for this internal catalog because users need predictable navigation

IMPORT WORKSPACE

Design an Excel import workflow that feels safe and deliberate.

Stages:

1. Upload workbook
2. Select worksheet
3. Review headers
4. Map columns
5. Preview rows
6. Validate
7. Explicit commit
8. Show result summary

Visual priorities:

- Make the commit action clearly destructive or high-impact
- Use a confirmation step
- Show scanned, imported, skipped, and duplicate counts
- Show row-level issues without dumping sensitive data
- Make formulas and unsupported values visibly marked
- Show progress/loading states
- Never make import look like an instant, unreviewed upload

Import history:

- Use a compact table or timeline
- Show filename, date, status, scanned count, imported count, skipped count
- Allow opening a batch detail
- Use semantic status badges:
  - Completed
  - Partial
  - Failed
  - Replayed

RESPONSIVE BEHAVIOR

- Mobile: 320–599px
- Tablet: 600–959px
- Desktop: 960–1439px

Requirements:

- No horizontal page overflow
- Cards collapse naturally
- Header actions wrap safely
- Search controls become stacked
- Detail fields become one column on mobile
- Image remains prominent on every device
- Buttons have comfortable touch targets

ACCESSIBILITY

Follow WCAG-minded practices:

- Keyboard navigation for every interactive element
- Visible focus ring
- Proper button semantics
- Meaningful labels
- Sufficient text/background contrast
- Do not use color alone to communicate status
- Accessible empty and loading states
- Image alt text rules
- Respect prefers-reduced-motion
- Avoid flashing or aggressive animations

MOTION

- 120–220ms transitions
- Gentle card hover elevation or border change
- Smooth drawer/page transitions
- Skeleton loading for large content areas
- No excessive parallax
- No animated gradients
- No decorative motion that delays task completion
